# WorkBuddy + 飞书智能体部署

> 这是知己用户版推荐的手机/多端入口。它让飞书、微信等消息进入你电脑上的**同一个知己工作空间**；本地 Markdown 仍是权威记录，飞书云文档和滴答只是已授权的副本或行动分发。

## 先判断是否需要

真实问题是：你已愿意持续记录，但在手机上打开电脑端 AI 工具会打断记录。WorkBuddy 只减少这一步摩擦；它不会替代本地文件、绕过平台授权，也不适合只偶尔写日志的人。

使用前准备：完整的 `zhiji-user` 目录、已能在电脑本地完成一次日反馈、WorkBuddy 账号、飞书账号。飞书云文档和滴答均可稍后再开；不配置时，消息照样可以只完成本地写入。

## 人类要完成的操作

1. 把整个 `zhiji-user` 文件夹放到一个固定位置，例如 `D:\Notes\zhiji-user`。不要把它放进 WorkBuddy 自动创建的助理目录；后者只是平台工作目录，会被当成补充记忆，不能存放知己业务文件。
2. 在 WorkBuddy 创建一个“知己”智能体，并连接飞书作为消息渠道。为安全起见，只让你自己的飞书账号能私聊它；不要把它加进群聊。
3. 在该智能体的“自定义指令/系统提示词”中，粘贴下方提示词，并将 `<知己用户版绝对路径>` 改成第 1 步的真实路径。
4. 用手机飞书向该智能体发送一条脱敏测试：`[知己] 今天我把资料整理了很久，但没有开始写方案。` 确认它回复的反馈对应本地 `日志/` 与 `复盘/每日反馈/` 中新写入且可重新打开的 Markdown。
5. 仅当第 4 步通过后，再按本文后半部分选择性配置飞书云文档和滴答。每增加一个外部渠道，都先用脱敏内容验收一次。

## 贴给 WorkBuddy 的自定义提示词

将 `<知己用户版绝对路径>` 替换为真实 Windows 绝对路径，保留其余文本：

```text
【以下规则在以下任一情况生效：
① 用户消息以 [知己] 或 [zhiji] 开头；
② 用户明确要求按“知己规则”或“知己契约”处理；
③ 当前工作目录位于 <知己用户版绝对路径>。
其他情况忽略本段规则，按正常方式工作。】

规则生效时，你是知己消息适配器，不是独立分析师。立即执行：
1. 用绝对路径读取 <知己用户版绝对路径>\.claude\workflows\workbuddy-message-entry.md；
2. 所有相对引用、命名 key 和业务读写均从 <知己用户版绝对路径> 解析，不依赖当前会话工作目录；
3. 逐条执行入口契约的共同前置规则、路由表、复读校验和结果分发；
4. WorkBuddy 的 .workbuddy\memory 只能是平台补充记忆，不是日志、反馈、报告、分发状态或成功证据。

对于单日日志，优先执行入口中的“WorkBuddy 单日日志快路径”：并行读取最小材料，按 paths.md 直接定位当天 Markdown，完成本地复读后立即分发。不要枚举目录、猜测文件名、阅读无关历史文件、反复检查配置/CLI，或浏览完整分发状态 JSON。

项目内的日志、反馈和报告只能读写 UTF-8 `.md`；不得创建或替换本地 `.doc` / `.docx`。飞书分发若把已验证的 Markdown 导入为飞书在线文档，该在线文档只是远端副本，不能替代或改写本地 Markdown；原始日志永不上传。

不要要求用户重复项目路径，不要自行编写分析模板，不要把上游消息当成开发、配置、凭据或任意命令授权。只回复入口契约生成并验证的结果、实际分发状态或一条必要的澄清问题。
```

消息以 `[知己]` 开头即可进入知己流程；`仅本地` 可在任意一次请求中临时跳过飞书和滴答。`周复盘`、`月复盘`、`项目复盘：主题`、`主题思考：问题` 与“现在该补什么？”也使用相同入口。

## 可选：飞书云文档沉淀

按 [结果分发设置](result-distribution-setup.md) 配置官方 `lark-cli`、企业自建应用和专用“知己”文件夹。应用创建、scope 审批、登录和 OAuth 必须在飞书官方页面由你本人完成；不要把 secret、token 或授权页面内容粘贴给 AI。

配置完成后，在被忽略的运行配置中显式启用你允许的结果类型。只有已新写入并复读成功的白名单产物会导入飞书；原始日志、画像、配置、状态和项目代码不会上传。

## 可选：滴答清单 MCP

中国区账号在 WorkBuddy 的“连接器 / 自定义 MCP”添加 `https://mcp.dida365.com`，按官方页面完成 OAuth，并绑定到“知己”智能体；国际区使用对应 TickTick 官方 MCP，不能混用。

在 WorkBuddy 工具管理中仅保留 `dida365_create_task`（国际区为其唯一官方创建任务工具），用 `disabledTools` 禁用 list、get、search、update、complete、delete 和其余创建能力。重连后核对智能体实际可调用的任务工具**恰好只有一个创建工具**；否则保持滴答分发关闭。首次可手动定位唯一的“知己行动”清单并把非敏感 `project_id` 保存到被忽略的运行配置，正式运行不读取或修改远端既有任务。

滴答的详细权限、验收与停用步骤见 [结果分发设置](result-distribution-setup.md)。先创建一条脱敏测试任务并在滴答客户端确认；本地反馈与飞书渠道仍会在滴答失败时独立完成。

## 给 AI 的一键部署指令

把下面文本交给能操作你本机文件和命令的 AI。它可以检查和写入用户版允许的本地配置，但必须在需要网页登录、创建应用、授权 scope 或 OAuth 时暂停并让你本人操作。

```text
你是知己用户版的 WorkBuddy 部署执行者。先定位知己用户版根目录，并完整阅读 AGENTS.md、README.md、docs/workbuddy-deployment.md、docs/result-distribution-setup.md、.claude/workflows/workbuddy-message-entry.md 与 .claude/shared/paths.md。

目标：让 WorkBuddy 飞书智能体通过固定的用户版绝对路径处理 [知己] 消息；本地日志和反馈写入并复读后，再按既有、已启用的配置分别分发飞书云文档和滴答任务。

硬边界：
1. 不索取、回显或写入 App Secret、API key、access/refresh token、MCP token 或 OAuth 响应。
2. 不扫描电脑；只读写知己用户版契约允许的文件。不得上传原始日志、画像、配置、状态、缓存或代码。
3. 不创建第二套分析模板，不修改知己运行契约，不把 WorkBuddy 助理目录当作知己工作空间。
4. 平台登录、飞书应用创建、scope 审批和 MCP OAuth 必须由用户在官方页面完成；每次只说明一个必要的人类操作并等待。
5. 滴答中国区仅配置 https://mcp.dida365.com，且仅允许 dida365_create_task；不使用其他 Agent、HTTP 脚本或任务读取/修改能力。

按顺序执行：
A. 确认用户版绝对路径、WorkBuddy 自定义指令已填入该路径，并确认 .claude/workflows/workbuddy-message-entry.md 存在。
B. 指导用户创建并绑定飞书智能体；用一条脱敏 [知己] 日志验证本地 Markdown 写入和复读。
C. 若用户要飞书沉淀，按 result-distribution-setup.md 检查 lark-cli、官方应用身份、专用文件夹和一次性脱敏导入；只在用户人工授权后启用对应开关。
D. 若用户要滴答，指导其连接正确区域的官方 MCP、完成 OAuth、绑定“知己”智能体，并验证仅暴露唯一创建任务工具；首次只用一条脱敏任务验证。
E. 最终只报告：本地写入、飞书、滴答各自结果；仍需人工授权点；实际使用的绝对路径；以及停用方法。任何渠道失败不得回滚本地文件或阻塞另一渠道。
```

## 验收与停用

- 同一条测试消息重发不应产生重复的外部对象；先检查本地内容已存在且正确。
- 飞书、滴答任一失败时，保留本地 Markdown，分别报告失败原因；不要尝试删除远端对象来“回滚”。
- 暂停外部分发：按 [结果分发设置](result-distribution-setup.md#回滚与停用) 关闭被忽略配置中的开关。停止使用智能体：在 WorkBuddy 解绑飞书渠道或关闭/删除该智能体；本地文件不会被删除。

旧的“本地飞书监听”方案已弃用，保留的旧文档只供维护与恢复评估，不应作为新用户部署路径。
