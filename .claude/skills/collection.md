# 收藏吃灰库收录

仅当用户明确要求收录到“收藏吃灰库”时执行；普通聊天、泛泛提及收藏或主题时不得写入。

## 1. 确认输入

1. 从用户表达中提取主题；未提供主题时只询问主题。
2. 读取 `.claude/shared/paths.md`，使用 `context.collection_dir` 与 `context.collection_topic`。
3. 清理主题和标题中的路径不安全字符，并确认目标文件仍在 `context.collection_dir` 内。
4. 用户只提供无法读取的链接时，请其粘贴原文或摘录；不得编造摘要或关键词。

## 2. 保存格式

根据原文生成准确、简短的摘要和方便后续自然语言检索的关键词。创建主题目录后，严格按以下格式写入：

```markdown
# 标题

## 摘要

## 关键词

## 原文 / 摘录全文

## 原文链接
```

原文链接未提供时，在对应章节写“未提供”。原文或摘录全文保持用户提供的内容，不擅自补写。

## 3. 防止误覆盖

写入前检查同一主题目录中是否已有相同链接或同名文件；如有，先说明冲突并询问用户更新还是新建。完成后回报保存路径。

## 4. 附件边界

用户明确收录项目外的 PDF、图片、音视频或其他附件时，先复制到对应收藏主题目录，并确认复制后的真实路径仍位于 `context.collection_dir` 内。不得直接上传项目外路径，也不得因为文件位于项目目录就推断它应被收录。项目代码、配置、凭证、状态、缓存和临时文件不得作为收藏附件分发。

## 5. 飞书分发

读取 `.claude/shared/contracts/result-distribution.md`。本次请求明确包含“仅本地”时，收藏完成本地写入、附件复制和复读后不调用结果分发；否则，只有本轮明确收录并完成**新写入**后，才从磁盘**重新读取**非空收藏条目并调用 `distribute context.collection_topic <resolved-local-path>`。附件先复制到对应收藏主题目录并验证非空后，调用 `distribute context.collection_attachment <resolved-local-path>`。

已有收藏只读展示、同名冲突未裁决、缓存命中、复制/写入失败或路径校验失败时不调用结果分发。分发摘要只追加到聊天，不写入收藏正文；飞书失败不影响本地收录成功。
