# 主题思考契约

## 适用边界

本契约只处理用户主动与 AI 探讨后形成、且经用户确认值得长期保留的认识。不从日志、日反馈或复盘自动摘录思考，不保存完整聊天记录，也不把 AI 单方面观点写成用户认识。

## 探讨与确认

讨论时区分事实、推断、建议和价值判断，检查依据、反例、适用边界与未决问题。AI 可以严肃挑战用户的价值判断和目标选择，但必须明确给出证据缺口、反例、推理跳跃、价值冲突、风险或替代解释之一；不能把 AI 偏好伪装成客观事实。形成可沉淀认识后，先向用户展示主题归纳与变更摘要。未经用户确认不得创建、写入或更新任何主题文件。

用户明确要求“依据第一性原理分析”、复核或压缩既有主题思考时，读取 `.claude/shared/contracts/first-principles-analysis.md`。价值判断仍以用户选择为主；AI 只能指出冲突、代价、反例或证据缺口。

## 动态主题与文件安全

主题不使用白名单或预置分类，允许根据用户确认的主题名创建任意新主题。将主题名映射为 `context.thinking_topic` 前，去除 `/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|` 等路径分隔符或不安全字符，并确认解析后的目标仍位于 `context.thinking_dir` 内。

名称与已有主题相同或近义时，优先更新已有主题或请用户选择。不得越界写入，不得静默覆盖无关文件。首次保存时创建目录和 `context.thinking_index`；新主题同时写入主题文件与索引。

## 主题文件结构

主题文件默认包含 YAML frontmatter、一个前置执行入口，以及以下六个陈述式板块：

0. `0. 当前行动卡`：放在正文最前面，只列当前最小必要行动；条目按需增减，并写清触发场景与观察或停止条件。没有合格行动时明确写“当前不行动”及等待条件；主题思考不默认定期回访或周反馈，读者不必读完整篇也能知道下次遇到同类问题时怎么做。
1. `1. 当前问题`：记录重复现象、情境、感受和冲突，不抢先解释原因；合并同义问题，但保留可回查的问题痕迹。
2. `2. 当前判断`：区分事实、推断和价值判断；AI 的观点不得伪装成用户认识。
3. `3. 依据来源与思考校正`：记录来源、反例、证据缺口、推理跳跃、价值冲突、风险或替代解释；严肃审查至少指出其中一项。
4. `4. 值得保留的行动`：记录有证据支持、符合用户价值或已有正向结果、值得长期反复使用的行动；有合格长期行动时使用“长期动作 / 解决的问题 / 具体做法 / 使用边界”四列表，避免写成一次性任务、抽象口号或过细技巧；没有合格长期行动时明确写“当前无长期行动”及等待条件，不虚构表格条目。
5. `5. 行动验证与复查`：有进行中的行动实验时，同时只保留一个，用编号步骤写明触发条件、最小动作、预期观察和验证时间；没有进行中实验时，只写当前行动卡的验证、停止或转向条件，不重复行动步骤。未经验证的方案不得写成答案。
6. `6. 我的观点演化路径`：新认识与旧观点冲突时，先展示“保留 / 修正 / 新增反例 / 仍未解决”的变更摘要；只有实质变化才记录观点演化，包含日期、旧观点、改变依据和新观点。

更新主题时优先修订前五部分。详细日志、文章和引用只保留来源入口，不把主题文件扩写成会话转录或资料仓库。

六个板块是帮助用户检查思考闭环的默认结构清单，不要求各部分篇幅相等。每一部分按证据、问题复杂度和行动需要决定具体程度：有明确行动或高风险判断时写细；证据不足、没有新认识或与当前行动无关时可以短写并说明原因。不得为了填满标题而平均扩写泛泛原则。标准主题使用 `0.` 到 `6.` 的编号标题固定阅读路径；`0. 当前行动卡` 应只做短期入口并引用 `4. 值得保留的行动` 中的长期动作，不重复堆叠完整说明；`4. 值得保留的行动` 和 `5. 行动验证与复查` 必须优先服务执行：前者写可复用做法，后者写进行中实验或当前验证、停止与转向条件。

### 自定义结构例外

只有同时满足以下条件，且用户明确确认采用替代结构时，主题才可不使用 0–6 标准标题：

1. 第一性原理复核表明，标准结构会重复现有主题、遮蔽真正的调用入口，或把本应是一张地图/准则/对照表的问题误写成线性因果报告。
2. 替代结构能更直接地改变当前判断、下一步行动或验证方式，而不只是更有新意、篇幅更短或规避难写部分。
3. 写入前已说明并记录该主题的唯一职责，以及与至少一个相邻主题的转向边界。

自定义主题在 frontmatter 写明 `format` 和 `semantic_role`；标题可以按内容改写，但必须保留以下语义部件：前置执行入口或“当前不行动”、唯一职责与转向、事实/推断/价值的必要区分、来源与至少一项思考校正、可观察的行动验证或等待条件。它不得借格式例外省略证据、行动质量、观点演化或用户确认边界。

自定义结构只服务当前确有证据的主题，不据此修改通用模板，也不把一次成功的表达形式升级为默认格式。若后续验证显示该格式没有降低调用摩擦或仍与相邻主题重复，应恢复标准结构、合并或删除。

## 内容质量与行动门槛

先按“真实问题 → 已知事实 → 关键假设 → 不可消除的约束与代价 → 最小可验证杠杆”审查主题。每段内容只有能改变当前判断、下一步行动或验证方式时才保留；否则删除、合并为必要背景，或短写暂不展开的原因。事实、推断、价值取舍和未验证假设必须分开。只有证据冲突、高风险或不可逆代价、复杂因果，或反例会改变当前选择时才展开；不能用篇幅代替证据。

不设置行动卡、长期行动或实验步骤的最低数量。每项行动必须同时直接回应当前问题或关键约束、处于用户可控范围、有触发条件与最小动作，并有可观察的结果来判断继续、调整或停止；不满足任一项不得列入。没有合格行动时，明确写“当前不行动”及等待的证据、条件或决策。行动卡只保留当前最小必要入口；长期行动只保留有证据、稳定价值取向或正向结果支撑的做法；实验步骤按需写，不得为凑步骤填充，且同时仍只保留一个进行中的行动实验。

## 默认质量审查与合并更新

主题的创建和更新默认执行第一性原理质量审查；用户不必额外说“依据第一性原理分析”。先检查真实问题、事实、关键假设、约束与代价、最小验证杠杆，再决定是否写入。显式要求第一性原理分析时，可以展开更深复核，但不是质量闸门的开关。

每条候选判断、反例、行动或来源写入前，必须与现有内容比较，并按顺序选择：`保留`（仍是必要依据）、`修正`（核心成立但边界变化）、`替换`（新证据否定旧结论）、`合并`（同一问题的重复表达）、`归档到观点演化`（历史变化仍有解释价值）或`不写入`（不改变判断、行动或验证）。不得未经比较直接追加内容；来源材料只保留来源入口，不复制为主题正文。

行动新增前检查是否重复、被替代或已失效。完成或停止、被替代的行动从 `0. 当前行动卡` 与 `5. 行动验证与复查` 移除；需要保留解释时，在 `6. 我的观点演化路径` 简短记录原因。`4. 值得保留的行动` 只收录可复用的稳定做法，当前行动卡只显示当前仍有效的最小入口。

## 语义质量审查与全量优化

全量审查不以字数、行动数量或格式整齐作为质量指标，而按六个维度逐项检查：

1. **主题内重复**：同一判断、行动、例子或边界在不同板块重复时，合并到最能支持当前判断或执行的位置，其余位置引用或删除。
2. **跨主题重叠**：两个主题解释同一问题、给出同一行动或争夺同一边界时，指定一个主主题；其他主题只保留最小引用，必要时建议合并主题。
3. **过期与冲突**：旧判断被新证据否定、缩小适用范围，或与当前表达冲突时，修正、替换或归档到观点演化路径。
4. **证据质量**：事实、推断、价值选择不得混写；缺少来源、反例或适用条件的判断不得作为稳定结论。
5. **行动质量**：行动必须仍回应当前问题、可控、可触发、可验证；完成、失效、被替代或重复的行动删除或归档。
6. **篇幅价值**：只有改变当前判断、行动或验证的信息才保留；关键证据、高风险边界和必要历史变化即使较长也不因压缩而删除。

全量审查对每项问题记录 `保留 / 合并 / 删除 / 修正 / 替换 / 归档` 决策及证据，并执行对应的实际文件修改；不得以审查记录代替主题优化。判断无需改动的主题也必须说明保留依据。跨主题重叠映射应写明主主题、引用主题和各自保留的最小职责。

### 审查边界与交付门槛

行动卡整理、固定周期清理、标题/格式统一或仅标记“已检查”，都不是全量语义审查的完成证据；它们至多是某一维度的输入或局部修改。全量审查的交付物必须同时包含：每份主题的重复、冲突、过期或低价值内容清单；每项的决策及证据；对应的正文文件级修改；跨主题主从映射；以及修改后的复核，确认压缩没有丢失当前关键判断、适用边界、必要历史依据或高风险限制。

审查计划应以语义重复和当前有效性为中心，而不是围绕格式整齐、行动数量或实验周期组织；只有在新信息改变判断、行动或验证时，才继续写入或扩展主题。

### 全量语义审查验收模板

完成全量审查前，必须按下列模板复核并输出；任一项缺失时不得宣称“全量审查完成”：

```markdown
## 范围与完整性
- 已审查：N/N 份主题；缺失或跳过：无 / 文件名与原因。

## 逐篇决定
| 主题 | 六维问题与正文位置 | 决策及证据 | 实际正文修改；若保留，说明删除会丢失什么 |
|---|---|---|---|

## 跨主题映射
| 主主题 | 引用主题 | 各自最小职责 |
|---|---|---|

## 修改后复核
- 压缩后仍保留的关键判断、适用边界、必要历史依据和高风险限制。
- 已验证主题结构、内部链接与运行契约；测试范围只能证明其实际覆盖的规则。
```

## 自动召回

普通提问涉及用户既有观点、长期困惑或价值判断时，先读取 `context.thinking_index`。只有主题、别名或核心问题明显相关时，才读取最多 2 个最相关主题文件；没有明显匹配就不读取详细主题。

回答必须明确告知用户参考了哪些历史主题。历史认识只是用户曾认可的起点，不是永久事实；当前表达与历史观点冲突时，以当前表达优先，指出可能的观点变化，并在需要更新时重新走确认流程。

召回历史主题时按“当前表达 -> 最近 90 天证据 -> 已验证长期模式 -> 90 天前未复核观点”的顺序确定权重。90 天前的具体观点不是自动失效，而是进入复查状态；引用时必须说明更新时间，并检查用户是否仍认可。核心价值、长期主题和已验证模式不因超过 90 天自动降级，但需要结合最近证据和反例判断是否仍适用。

## 高频链路边界

日反馈默认不读取思考库；只有当天日志明确涉及某主题，且不读取会导致重复或冲突建议时，才按需读取 1 个主题。周/月复盘只在思考已经影响行动、方向选择或反复困境时引用。

## 异常处理

- 索引存在但主题文件缺失：提示索引失效，不根据缺失内容回答。
- 多个近义主题：建议合并或请用户选择。
- 用户拒绝保存：不写文件，也不反复劝说。
- 用户请求删除：展示影响范围，确认后删除主题并更新索引。
- 主题长期未更新：说明更新时间并检查是否仍认可，不自动判定失效。
