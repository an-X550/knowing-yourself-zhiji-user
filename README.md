# ReflectLoop Agent Skill（知己用户版）

> 这是面向最终用户的可安装 Agent Skill 分发工作区：下载或复制完整目录，用 Codex 或 Claude 打开后，把真实记录交给知己完成“发现模式 → 形成行动 → 后续验证”。第一次使用请直接打开 [用户上手页](index.html)；浏览器版完整说明见 [用户使用说明](guide.html)。

> 把日常记录变成更可靠的行动：看见模式，试一个小改变，再用结果校准认识。

GitHub：[knowing-yourself-zhiji-user](https://github.com/an-X550/knowing-yourself-zhiji-user) · 产品总入口：[Reflectloop](https://github.com/an-X550/Reflectloop) · Windows Agent：[Reflectloop-Desktop-Agent](https://github.com/an-X550/Reflectloop-Desktop-Agent) · DSH 插件：[zhiji-dsh-plugin](https://github.com/an-X550/zhiji-dsh-plugin)

## 先判断这个仓库是否适合你

- 适合：你想在自己的文件夹中保存日志和复盘，并用 Codex 或 Claude 读取这套 Markdown 工作区；你愿意自己决定哪些内容写入、分发或验证。
- 不适合：你只想双击一个 Windows 应用；请使用 [ReflectLoop Desktop Agent](https://github.com/an-X550/Reflectloop-Desktop-Agent)。
- 不适合：你已经在 DeepSeek Harness 中运行；请使用 [ReflectLoop DSH Plugin](https://github.com/an-X550/zhiji-dsh-plugin)。
- 这不是主仓库的源码镜像。它是给最终用户安装和使用的分发包；本地 Markdown 是本工作区的记录权威，不能假设它会与其他仓库或其他入口自动同步。

## 知己是什么

知己是一套给中文个人日志使用的 AI 复盘系统。你写下发生的事、感受和行动；它帮你把不同日期的线索连起来，发现你自己不容易看到的重复模式，并把它变成一个可以在现实中检验的小行动。

它既不是日记代写工具，也不只是把日志总结得更漂亮。普通总结告诉你“发生了什么”；知己要帮助你回答“什么模式可能在反复发生、我下一步能试什么、结果是否支持这个判断”。

## 它适合谁

你不需要先养成完美的记日记习惯。只要你希望更清楚地理解自己并愿意记录后续结果，知己就适合你，尤其是在以下情况：

- 今天卡住、拖延、情绪反复，想知道可以先改变什么；
- 一段时间感觉“不太对”，想看见规律而非凭印象判断；
- 完成项目或经历一个阶段，想知道什么有效、什么需要重来；
- 长期目标、精力、关系或生活结构出现持续冲突；
- 有一些会影响生活判断的观点或资料，希望持续整理和修正。

知己不替你诊断心理或医疗问题，不替你决定人生，也不把单篇日志写成对你的最终结论。它的价值在于帮助你形成可被后续事实推翻、修正或支持的认识。

## 它为什么这样工作

一次日志只能提供片段；一次行动成功或失败也不足以说明根因。因此知己把“解释”和“验证”分开：

```text
记录事实 → 提出待验证的假说 → 尝试一个小行动 → 记录结果 → 校准认识
```

这让你避免把 AI 的一句话当答案，也避免只靠感觉重复同一种无效努力。

## 我现在该做什么？

| 你现在的情况 | 选择 | 你会得到什么 | 直接这样说 |
|---|---|---|---|
| 刚写完日志、今天卡住或想改变一个小问题 | 日反馈 | 一个关键洞察、一个小实验、下次观察点 | `帮我做今天的日志反馈` |
| 不知道该补日反馈、更新上下文还是做更长复盘 | 统一入口 | 根据材料和时间范围只推荐一条最优先路径 | `最近有什么该补？` / `我有遗漏吗？` |
| 日志写了几天，但不知道怎么写得更有用 | 日志教练 | 最该补的一类信息与写作建议 | `看看最近几天的日志质量，只告诉我优先改进什么` |
| 想理解一周、一月或一个项目的结果 | 阶段复盘 | 趋势、证据、反例与下一步 | `生成 2026-W28 周报` / `生成 2026 年 6 月月报` / `对 X 做项目复盘` |
| 长期目标、精力或生活结构持续冲突 | 人生设计 | 方向校准与可验证的小实验 | `我想重新检查最近的生活方向` |
| 想形成并持续修正一个长期观点 | 主题思考 | 经确认后保存的认识、依据与反例 | `先讨论这个问题，不要保存；形成认识后再问我是否写入` |
| 想保存文章、摘录或资料 | 收藏吃灰库 | 可检索的摘要、关键词、原文与链接 | `收录到收藏吃灰库/健身：` 加上内容或链接 |

日反馈优先于更长的报告：没有行动与验证时，更多总结通常不会带来更多改变。年度回顾依赖足够月报，材料不足时先完成最近一次日反馈、周报或月报。

你随时可以自然地问“最近有什么该补？”或“我有遗漏吗？”，系统会只推荐一项最优先路径。每次成功生成新的正式日反馈并完成验证沉淀后，系统也会额外检查一次；只有需要行动且同类提醒未在 7 天内出现过时，才显示一条 `🔔 提醒`。如果长时间没有新日志，系统不会后台弹窗或催办；提醒只建议你手动执行，不会自动修改 `current.md`、报告或其他个人内容。

## 第一次使用：完成一个最短闭环

**首次使用推荐从日反馈开始。** 其他功能需要更多时间跨度或材料；先完成一次短闭环，才能知道这套方式是否适合你。

1. 下载或复制完整的知己用户版目录，不要只保存 README。
2. 用能打开**整个**目录、读取项目指令并读写 Markdown 的工具（如 Codex 或 Claude Code）打开它。
3. 粘贴一段真实日志，然后发送：

```text
分析这篇日志。请找出一个我可能没看到的模式；区分事实与推断；只给我一个明天可验证的小实验。
```

例如：

```text
日志：今天本来要完成方案，但我一直整理资料，直到晚上也没开始正文。
```

下一次日志补充：

```text
上次实验：[做了 / 没做 / 做了一部分]
结果：[发生了什么]
判断：[支持原假说 / 出现反例 / 仍待验证]
```

这样做的原因是：一次分析只能给出可能有用的解释；后续结果才能判断这个解释和行动是否适合你。

## 它如何使用你的日志

日志不必套模板，`日志：`、`日记：` 或 `记录一下：` 开头的自由叙事都可以。写清发生了什么、你的感受、实际做法、结果差异和不确定之处，会提高分析质量。

AI 应该在证据不足时降低结论强度，而不是补完故事；一次实验没奏效，也只说明这次方法未奏效。你始终决定采纳、修改或拒绝建议，并保留对自身经历、价值与重大决定的最终解释权。

Claude 兼容命令：`/review`、`/daily-review today`、`/journal-coach`、`/weekly-review`、`/monthly-review`、`/project-review`、`/yearly-review`、`/life-design --quick`。在 Codex 中可直接使用上表自然语言。

可选结果分发默认关闭。启用后，飞书可把新生成的正式复盘、人生设计、已确认主题思考和明确收录的收藏及附件沉淀到固定“知己”目录；滴答只接收每日反馈、周复盘、月复盘和已确认主题思考中的合格行动，任务只含 SMART 化标题与截止时间。日反馈自动创建，周/月及主题经过对应确认；完成判断仍只读取后续日志。本地文件始终权威。若本次只想保存到电脑，在生成请求中直接说“仅本地”，本轮同时跳过飞书和滴答且不留下永久标记。设置方法见 [`docs/result-distribution-setup.md`](docs/result-distribution-setup.md)；不要把密钥交给聊天或项目文件。

一次性或周期性的纯提醒默认使用滴答清单原生通知；Codex 定时任务只在用户明确指定时例外。提醒只通知你手动开始，不会自动读取文件或生成复盘。

## WorkBuddy 飞书智能体（可选，推荐的手机/多端入口）

如果每天打开电脑端 AI 的摩擦太大，可用 WorkBuddy 的飞书智能体发送 `[知己] <日志正文>`。智能体会按固定绝对路径进入**你的知己用户版工作空间**：本地 Markdown 写入并复读后，才按你已启用的配置向飞书云文档和滴答分别分发。WorkBuddy 自己的助理目录只存平台记忆，不能代替知己项目目录。

- 按[WorkBuddy + 飞书智能体部署](docs/workbuddy-deployment.md)完成用户操作、自定义提示词、MCP 和 AI 一键部署。
- 飞书云文档沉淀、滴答 MCP 都是可选项；必须由你本人在官方页面完成登录、应用权限与 OAuth 授权。
- 本次只想保存到电脑时，说 `仅本地`，将同时跳过飞书和滴答。

分发包不包含开发者的账号、目录 token、滴答清单 ID、凭证或运行状态。每位用户必须在自己的飞书、滴答和 WorkBuddy 中完成授权；不要把密钥或 token 给 AI。旧的本地飞书监听方案已弃用，不应作为新用户部署路径。

## 结果保存与隐私

| 目录 | 内容 |
|---|---|
| `日志/` | 原始日志 |
| `复盘/每日反馈/` | 日反馈和日志教练报告 |
| `复盘/每周复盘/`、`复盘/每月复盘/`、`复盘/项目复盘/` | 阶段复盘 |
| `复盘/年度回顾/`、`复盘/人生设计/` | 长期回顾与方向校准 |
| `关于我/` | 长期上下文、验证沉淀与确认后的主题思考 |

请勿写入不愿交给当前 AI 服务商处理的敏感信息。真实日志默认不会进入 Git，但这不是加密或访问控制。若会填写真实画像，首次填写前运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/protect-private-data.ps1
```

它会将相关种子文件标记为 `skip-worktree`，减少误提交风险；换电脑或重新克隆后需再次执行。

## 常见问题

**AI 说得很有道理，要直接相信吗？** 不要。检查它引用了哪些日志事实、寻找反例，再用后续行动验证。

**没有按建议行动，是失败吗？** 不是。“没做”也是信息，可能说明行动门槛、时机或假说需要调整。

**日志很短还能分析吗？** 可以，但结论应更保守；补充一两项事实、感受、行动或结果即可。

## 当前版本与验证状态

当前用户版对应 `v1.27.15`。用户上手页、详细使用说明与可选集成说明均提供离线 HTML 阅读入口，并由用户版导出源统一维护。WorkBuddy 的唯一消息入口已随用户版导出；用户需自行配置飞书智能体、自定义提示词、飞书应用和滴答 MCP，并用脱敏内容验收。四来源滴答最小适配已通过自动化端到端模拟和官方 MCP 冒烟测试，可正式使用；正式运行使用首次设置保存的“知己行动”清单 ID，不查询任务或完成状态。飞书云文档写入不要求逐次用户授权，只有自动授予权限失败或专用用户实际不可见时才恢复授权，且不得通过重新导入制造副本。真实非 Markdown 收藏附件与新白名单产物仍需在日常使用中观察自动落位。
